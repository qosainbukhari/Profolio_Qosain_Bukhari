AI Accident Detection & Emergency Response

A full-stack web application around a custom YOLOv12 model. Operators upload road-scene images or video; the model detects accidents as fire, moderate or severe, incidents are recorded, and responders get email or WhatsApp alerts with annotated frames.

01The problem

Road accidents are often reported late, by whoever happens to pass by, and the first report rarely says how serious the scene is. The goal was a system where an operator can upload CCTV images or video, have a model flag accidents and their severity, and notify responders with evidence.

The model supports a human decision; it is not an emergency dispatch or a medical assessment. That shaped the design: every detection is stored with its confidence, boxes and media so a person can review it.

02Data

A 3-class road-scene dataset: fire, moderate and severe. I trained YOLOv12n for 40 epochs at 640 px and evaluated it once on a held-out test set of 1,800 images containing 2,443 objects.

03Approach

  1. Train the detector. Fine-tuned YOLOv12n (Ultralytics, PyTorch) for 40 epochs at 640 px, and kept the training curves, PR curves and confusion matrix with the model bundle.
  2. Serve it securely. A FastAPI backend with JWT role-based authentication. Images return annotated results immediately; videos run as background jobs with progress polling.
  3. Record every incident. SQLAlchemy and Alembic migrations on MySQL store events, confidence, boxes, media paths, statuses and audit information.
  4. Alert responders. Optional SMTP email and WhatsApp delivery send annotated frames, with a mock mode for safe demos. Gemini can write the incident assessment, with a deterministic fallback when no API key is set.
  5. Show it to operators. A React, Vite and Tailwind dashboard for history, alerts, analytics and generated assessments.
  6. Package and test. Docker Compose runs MySQL, the backend and the frontend together; Pytest covers the API, security, alerts and workflows.

06Limitations

  • Built for academic demonstration and controlled local deployment, not live emergency dispatch.
  • Video jobs are held in memory, which suits a single-process demo but not a multi-worker production setup.
  • Email and WhatsApp delivery depend on configuration and can fail; delivery status is stored so it can be checked.
