Chest CT-Scan Classification

Classifies chest CT scans as adenocarcinoma (a type of lung cancer) or normal using transfer learning on VGG16, built as a reproducible DVC pipeline with MLflow tracking on DagsHub and a Flask app for predictions. I built it while learning MLOps from a guided course project, then audited it and found a data leak.

01The problem

Classifying chest CT scans as adenocarcinoma or normal is a classic small-data medical imaging task, where transfer learning from ImageNet is the standard starting point. I used it to learn how a deep-learning project becomes a reproducible pipeline instead of a notebook.

02Data

A small two-class set of chest CT images (adenocarcinoma and normal), downloaded and unzipped by the ingestion stage. Images are resized to 224 × 224 and augmented with rotation, flips, shifts, shear and zoom during training.

03Approach

  1. Ingest. Download and unzip the CT images into the artifacts folder.
  2. Prepare the base model. VGG16 with ImageNet weights, the top removed and the base frozen, plus a new head: Flatten, Dropout(0.5), Dense(2, softmax).
  3. Train. Adam at a 0.01 learning rate, 5 epochs, batch size 16, with augmentation; all hyper-parameters live in params.yaml.
  4. Evaluate and track. Loss and accuracy go to scores.json and MLflow on DagsHub; credentials come from environment variables, never code.
  5. Serve. A Flask app accepts an uploaded scan and returns the prediction.

Validation splitone shared constant (the fix)

After the fix, the reported accuracy comes from images the model never trained on; the scores are regenerated with dvc repro.

The bug I found. The first version reported 100% accuracy. Training used validation_split=0.20 but evaluation used 0.30, so evaluation ran on the first 30% of each class, and a third of those images had been in the training set. The fix was a single shared VALIDATION_SPLIT constant used by both stages. Lesson: define the split in exactly one place.

06Limitations

  • Small dataset with only two classes: a learning project, not a medical tool.
  • There is no test set separate from validation yet; the next step is a held-out test split and a confusion matrix.
  • Grad-CAM heatmaps, to show which region drives each prediction, are planned.
