Document Q&A RAG Chatbot

A retrieval-augmented generation chatbot: PDFs are chunked, embedded with MiniLM and stored in a persistent ChromaDB index. Questions retrieve the most relevant chunks, and Llama 3.1 on Groq answers from them with page-level citations and conversation memory.

01The problem

Long PDFs such as lecture notes, research papers and textbooks are slow to search, and a plain LLM answers confidently without saying where its answer came from. For study or work notes you need answers that come from the document and show the page so you can check them.

02Data

I evaluated it by hand on 20 question and answer pairs across several PDFs, including an ML textbook, a research paper and lecture notes, scoring whether retrieval found the right passage and whether the answer stayed faithful to it.

03Approach

  1. Ingest. Extract the text from each uploaded PDF and split it into overlapping chunks that keep the source file and page number.
  2. Embed and store. Encode chunks with all-MiniLM-L6-v2 (Sentence Transformers) into a persistent ChromaDB index, so documents don't need re-embedding after a restart.
  3. Retrieve and answer. Semantic search pulls the closest chunks; the prompt combines them with the question and recent conversation, and Llama 3.1 8B on Groq writes the answer.
  4. Cite sources. Every answer returns the source file and page for each chunk it used, so the reader can check it.
  5. Ship it. FastAPI endpoints (/upload, /chat, /health) with startup model loading and structured logging, a Streamlit UI, Docker Compose, and Pytest on GitHub Actions.

06Limitations

  • The 20-pair manual evaluation is small; an automated evaluation set would give firmer numbers.
  • Retrieval is vector-only. Hybrid search (BM25 + vectors) would help with exact terms and names.
  • No authentication, response streaming or cloud deployment yet.
