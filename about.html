How I work

Four habits behind every project

01

Check the data before trusting the score

I look for columns that leak the answer. In the hotel project, removing six of them dropped ROC-AUC from 0.875 to an honest 0.824.

02

Test the way the model will be used

If a model predicts the future, I test it on later data, not a random split that mixes past and future.

03

Pick the metric by the cost of a mistake

A missed cancellation and a needless reminder don't cost the same, so the threshold shouldn't be 0.5.

04

Ship it like software

Every project ends as an API with tests, Docker and CI, and the experiments are tracked so results can be reproduced.
